## HYPOTHESIZE Phase - Managing Existing Test Plan

You already have a test plan that you created in a previous HYPOTHESIZE phase. Your goal now is to review and update this plan based on what you've learned.

### Current Situation
You returned to HYPOTHESIZE after completing some testing. This means you likely discovered new attack vectors or need to refine your investigation strategy.

### Available Actions

1. **Review the existing plan**: Look at the current test plan items and their status
   - Check which items are completed, pending, or skipped
   - Evaluate if the priorities still make sense based on your findings

2. **Complete todos**: Use `complete_todo` to mark any items you finished in the TEST phase
   - Set status to "completed" if you successfully tested the item
   - Set status to "skipped" if you determined the item is not relevant or feasible
   - Always provide a clear reason explaining what you found or why you skipped it

3. **Add new todos**: Use `add_todo` if you've discovered new investigation areas
   - Add high-priority items for critical security concerns discovered during testing
   - Add medium-priority items for interesting attack vectors worth exploring
   - Add low-priority items for nice-to-have investigations

4. **Transition to next phase**: Use `transition_phase` to move forward:
   - Transition to TEST phase if you have pending todos to work on
   - Transition to RECON phase if you need to gather more information first

### Important Guidelines

**DO NOT create a new test plan!** You already have one. Creating a new plan would discard your existing work and progress.

**DO update the existing plan** by completing items and adding new ones as needed.

**Prioritize based on findings**: If testing revealed critical vulnerabilities or high-risk areas, add those as high-priority items.

### Example Workflow

1. "I completed testing item X and found vulnerability Y. Let me mark it complete."
   → Call `complete_todo` with status="completed" and detailed findings

2. "While testing X, I discovered attack vector Z that wasn't in my plan."
   → Call `add_todo` with description of Z and appropriate priority

3. "I have 3 pending high-priority items to investigate."
   → Call `transition_phase` to TEST to continue working on them

4. "I need more information about component W before testing it."
   → Call `transition_phase` to RECON to gather additional information
